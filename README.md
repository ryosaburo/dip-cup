# 妄想ポーカー

`hackathon_idea.md` のゲーム仕様を `tech_stack.md` の技術構成（Next.js フロントエンド／Socket.io WSサーバーの分離構成）で実装したもの。

# URL
`https://dip-cup-frontend.vercel.app`

## 構成

npm workspacesモノレポ。

- `packages/shared` — フロントエンド／サーバー共通の型・ゲーム設定・ゲーム判定ロジック（純粋関数）
- `packages/server` — Socket.io WSサーバー（Express + Socket.io、ルーム管理・ラウンド判定をサーバー権威で実行）
- `packages/frontend` — Next.js（App Router）フロントエンド

## 開発フロー（ブランチ運用）

- `main` — 本番用。`dev` からのPRのみでマージする
- `dev` — 開発統合ブランチ。各作業ブランチはここに向けてPRを送る
- `feature/<内容>` — 新機能実装用。`dev` から分岐し、`dev` へPR（例: `feature/support-card-effects`）
- `fix/<内容>` — バグ修正用。`dev` から分岐し、`dev` へPR（例: `fix/round-result-sync`）

複数人での並行作業になるため、作業前に必ず最新の `dev` から新しいブランチを切ること。コンフリクトを避けるため、他人が触っているファイル・機能と重なる変更をする場合は事前に一声かける。

## セットアップ

```bash
npm install
```

`packages/server/.env`:

```
PORT=4000
CORS_ORIGIN=http://localhost:3000
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

`packages/frontend/.env.local`:

```
NEXT_PUBLIC_WS_URL=http://localhost:4000
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

Supabase関連の変数は任意。未設定でもゲスト対戦としてアプリは動作する（ログイン機能とその依存機能のみ無効化される）。設定する場合は `supabase/migrations/` 配下のSQLをSupabaseプロジェクトのSQL Editorで実行してテーブルを作成すること。

## 起動

```bash
npm run dev
```

`shared`（tscウォッチ）・`server`（:4000）・`frontend`（:3000）が同時に起動する。`shared`の型やロジックを変更した場合、ウォッチが自動で`dist`を再ビルドするので、サーバー・フロントエンドの再起動は基本不要（フロントエンドはHMRで反映、サーバーはtsx watchで自動再起動）。

## 動作確認手順（手動E2E）

1. ブラウザ2タブで `http://localhost:3000` を開く
2. タブ1: プレイヤー名を入力し「ルーム作成」→ 発行されたルームコードをコピー
3. タブ2: 別のプレイヤー名を入力し、コードを入力して「入室する」
4. 攻撃側のタブでランダムに配られた現実カード3種類のいずれか、または妄想カード（ダメージ／回復と申告量を指定）を選び「この内容で攻撃する」
5. 防御側のタブに申告ダメージ量が表示されるので、「現実」か「妄想」かを予想して選択
6. 判定結果（見破ったか／見破られたか・ダメージ・残りライフ・妄想ゲージ）が両画面に表示される
7. 「次のターンへ」で攻守交代し、どちらかのライフが0、または妄想ゲージが100%になるまで繰り返す

## CI

`dev`・`main`宛のPRでは `.github/workflows/ci.yml` が自動実行される（sharedのビルド／server・frontendの型チェック／frontendのLint／serverのユニットテスト／frontendの本番ビルド）。`build-and-test` がRequired status checkとして設定されているため、CIが通らないとマージできない。

`packages/server/test/gameEngine.test.ts` が、見破り／見破られの判定・現実カード12種類それぞれの効果・継続ダメージ／継続回復・妄想ゲージの増減・回復の上限・即敗北抽選・勝敗判定・現実カードのランダム配布（3種類・重複なし）を検証する（Node標準のテストランナーを使用、追加依存なし）。

## ゲームバランスの暫定値

現実カード各種のダメージ量・妄想カードの申告ダメージ範囲・妄想ゲージの増減量・開始時ライフは `hackathon_idea.md` 時点で未確定だったため、`packages/shared/src/gameConfig.ts` に暫定値を集約している。実プレイでの調整はこのファイルの数値を変更するだけでよい。

## 実装上の仮定（doc未記載のため採用したルール）

同時選択ではなく、**攻撃側と防御側が交互に手番を持つターン制**を採用している。

1. 攻撃側は、現実カード12種類の中からそのターン用にランダムで配られた3種類のいずれか、または妄想カードを選ぶ（妄想の場合はその場で申告ダメージ量も入力する）。配られる3種類は攻守交代のたびに毎回引き直される
2. 防御側は攻撃側が確定させた申告ダメージ量を確認したうえで、それが「現実」か「妄想」かを予想する（現実カードのどれかまでは予想しない）
3. 判定して結果を両者に通知し、次のターンは攻守交代する（先攻はランダムに決定）

- **防御側が攻撃側のカードの種類を見破った場合**：カードの効果は攻撃側にそのまま返らず、**ダメージ系カードは攻撃側への反動ダメージ**、**回復系カードは見破った防御側自身がそのライフを回復する**という形で処理される
  - 見破られたのが**妄想カード**だった場合：ダメージ申告なら申告量が攻撃側への反動ダメージになり、回復申告なら見破った防御側が申告量だけ回復する。いずれの場合も攻撃側の妄想ゲージが申告量だけ上がり、さらに見破られる直前の妄想ゲージ%を確率とした抽選があり、外れると即座に妄想ゲージが100%になる（＝即敗北扱い）
  - 見破られたのが**現実カード**だった場合：ダメージ系カードは反動ダメージのみで妄想ゲージは変動しない（「疼く傷跡」は継続ダメージも含めて攻撃側自身が受ける）。**回復系カード**（休息・無理な回復・緩やかな回復）は見破った防御側がそのライフを回復し、攻撃側は回復できない。**瞑想**（ゲージ系）のみ例外的にゲージが反転して上がる
- **見破られなかった場合**：申告・計算どおりの効果が発生する
  - **妄想カード**が成功した場合：ダメージ申告なら申告量がそのまま防御側に通り、回復申告なら攻撃側自身が申告量だけ回復する。いずれの場合も攻撃側・防御側どちらの妄想ゲージも変動しない
  - **現実カード**は種類ごとに固有の効果を持つ（`packages/shared/src/gameConfig.ts`の`REALITY_CARD_CONFIG`参照）：
    - **着実な一撃**：固定20ダメージ。成功すると攻撃側の妄想ゲージが15%下がる
    - **圧殺の一撃**：固定25ダメージ。攻撃側の妄想ゲージが60%以上なら2倍（50）になる
    - **疼く傷跡**：10ダメージ＋以後3ターン、ターン終了時ごとに10ダメージが入り続ける継続ダメージ（攻守交代を挟んでも減衰せず入り続ける）
    - **妄想の解放**：攻撃側の現在の妄想ゲージの値（%）がそのままダメージになる
    - **痛烈な一撃**：固定30ダメージ
    - **素早い一撃**：固定20ダメージ
    - **小さな一撃**：固定10ダメージ
    - **休息**：成功すると攻撃側のライフが30回復。**見破られると攻撃側は回復できず、見破った防御側のライフが30回復する**
    - **瞑想**：成功すると攻撃側の妄想ゲージが30%下がる。**見破られると逆に30%上がる**（反転）。ダメージは発生しない
    - **無理な回復**：成功すると攻撃側のライフが50回復。**見破られると攻撃側は回復できず、見破った防御側のライフが50回復する**。妄想ゲージ+20%は見破られたかどうかに関わらず常に攻撃側に発生する（デバフ前提の効果）
    - **緩やかな回復**：以後3ターン、ターン終了時ごとに攻撃側のライフが10回復し続ける継続回復。**見破られると攻撃側は回復できず、以後3ターン見破った防御側のライフが10ずつ回復し続ける**。このターン自体には即時効果はない
    - **吸血**：攻撃側が1〜50の範囲で申告したダメージを相手に与え、成功すると同じ量だけ攻撃側も回復する。**見破られると回復はできず、申告した量の反動ダメージのみが攻撃側に入る**（ゲージ変動なし）
    - 上記のうちゲージ変動が明記されていないカードは妄想ゲージを変動させない
  - ライフの回復は開始ライフ（100）を上限にクランプされる
- 開始ライフは100固定。**ライフが0、または妄想ゲージが100%に達したプレイヤーが敗北**。両者が同時に敗北条件を満たした場合は引き分け
- **妄想カードを見破られずに5回成功させたプレイヤーは、ライフや妄想ゲージの状況に関わらずその時点で即座に勝利する**（`DELUSION_SUCCESS_WIN_COUNT`。見破られた回数はカウントされず、リセットもされない累計回数）
- サポートカードは廃止し、現実／妄想の読み合いのみのシンプルな仕組みにしている
