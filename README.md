# AIエージェント学習対戦ゲーム

`hackathon_idea.md` のゲーム仕様を `tech_stack.md` の技術構成（Next.js フロントエンド／Socket.io WSサーバーの分離構成）で実装したもの。

## 構成

npm workspacesモノレポ。

- `packages/shared` — フロントエンド／サーバー共通の型・ゲーム設定・ゲーム判定ロジック（純粋関数）
- `packages/server` — Socket.io WSサーバー（Express + Socket.io、ルーム管理・ラウンド判定をサーバー権威で実行）
- `packages/frontend` — Next.js（App Router）フロントエンド

## 開発フロー（ブランチ運用）

- `main` — 本番用。`dev` からのPRのみでマージする
- `dev` — 開発統合ブランチ。各作業ブランチはここに向けてPRを送る
- `feature/<内容>` — 新機能実装用。`dev` から分岐し、`dev` へPR（例: `feature/support-card-effects`）
- `fix/<内容>` — バグ修正用。`dev` から分岐し、`dev` へPR（例: `fix/round-result-sync`）

複数人での並行作業になるため、作業前に必ず最新の `dev` から新しいブランチを切ること。コンフリクトを避けるため、他人が触っているファイル・機能と重なる変更をする場合は事前に一声かける。

## セットアップ

```bash
npm install
```

`packages/server/.env`:

```
PORT=4000
CORS_ORIGIN=http://localhost:3000
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

`packages/frontend/.env.local`:

```
NEXT_PUBLIC_WS_URL=http://localhost:4000
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

Supabase関連の変数は任意。未設定でもゲスト対戦としてアプリは動作する（ログイン機能とその依存機能のみ無効化される）。設定する場合は `supabase/migrations/` 配下のSQLをSupabaseプロジェクトのSQL Editorで実行してテーブルを作成すること。

## 起動

```bash
npm run dev
```

`shared`（tscウォッチ）・`server`（:4000）・`frontend`（:3000）が同時に起動する。`shared`の型やロジックを変更した場合、ウォッチが自動で`dist`を再ビルドするので、サーバー・フロントエンドの再起動は基本不要（フロントエンドはHMRで反映、サーバーはtsx watchで自動再起動）。

## 動作確認手順（手動E2E）

1. ブラウザ2タブで `http://localhost:3000` を開く
2. タブ1: プレイヤー名を入力し「ルーム作成」→ 発行されたルームコードをコピー
3. タブ2: 別のプレイヤー名を入力し、コードを入力して「入室する」
4. 攻撃側のタブで「現実」か「妄想」のカードを選び（妄想なら申告ダメージ量も指定）「この内容で攻撃する」
5. 防御側のタブに申告ダメージ量が表示されるので、「現実」か「妄想」かを予想して選択
6. 判定結果（見破ったか／見破られたか・ダメージ・残りライフ・妄想ゲージ）が両画面に表示される
7. 「次のターンへ」で攻守交代し、どちらかのライフが0、または妄想ゲージが100%になるまで繰り返す

## CI

`dev`・`main`宛のPRでは `.github/workflows/ci.yml` が自動実行される（sharedのビルド／server・frontendの型チェック／frontendのLint／serverのユニットテスト／frontendの本番ビルド）。`build-and-test` がRequired status checkとして設定されているため、CIが通らないとマージできない。

`packages/server/test/gameEngine.test.ts` が、見破り／見破られの判定・ダメージ計算・妄想ゲージの増減・即敗北抽選・勝敗判定を検証する（Node標準のテストランナーを使用、追加依存なし）。

## ゲームバランスの暫定値

現実カードの固定ダメージ・妄想カードの申告ダメージ範囲・妄想ゲージの増減量・開始時ライフは `hackathon_idea.md` 時点で未確定だったため、`packages/shared/src/gameConfig.ts` に暫定値を集約している。実プレイでの調整はこのファイルの数値を変更するだけでよい。

## 実装上の仮定（doc未記載のため採用したルール）

同時選択ではなく、**攻撃側と防御側が交互に手番を持つターン制**を採用している。

1. 攻撃側が「現実」か「妄想」のカードを選ぶ（妄想の場合はその場で申告ダメージ量も入力する）
2. 防御側は攻撃側が確定させた申告ダメージ量を確認したうえで、それが「現実」か「妄想」かを予想する
3. 判定して結果を両者に通知し、次のターンは攻守交代する（先攻はルーム作成者）

- **防御側が攻撃側のカードの種類を見破った場合**：カードの効果は防御側ではなく攻撃側に跳ね返る（自傷ダメージ）
  - 見破られたのが**妄想カード**だった場合：反動ダメージに加え、攻撃側の妄想ゲージが申告していたダメージ量だけ上がる。さらに、見破られる直前の妄想ゲージ%を確率とした抽選があり、外れると即座に妄想ゲージが100%になる（＝即敗北扱い）
  - 見破られたのが**現実カード**だった場合：反動ダメージのみで、妄想ゲージは変動しない
- **見破られなかった場合**：申告どおりのダメージが防御側に通る
  - **現実カード**が成功した場合：固定ダメージに加え、攻撃側の妄想ゲージが一定%下がる（回復）
  - **妄想カード**が成功した場合：申告したダメージがそのまま通るが、攻撃側の妄想ゲージは変動しない（防御側の妄想ゲージも一切変動しない）
- 開始ライフは100固定。**ライフが0、または妄想ゲージが100%に達したプレイヤーが敗北**。両者が同時に敗北条件を満たした場合は引き分け
- サポートカードは廃止し、現実／妄想の読み合いのみのシンプルな仕組みにしている
